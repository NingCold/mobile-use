# 下一步：缩短未知页面到正确动作之间的时间

已知目标可以连续执行。需要优先改进的是：页面切换后，旧目标已消失，却花了多轮截图去证明它不在原处。

1. **任务端先区分“当前步骤已完成”和“下一步点哪里”。** 两者不应共用一段会随内容变化的按钮文案。具体页面、允许的分支、文案和完成标准留在调用方。记录稳定路径与换布局路径各自的基线。
2. **在服务端验证有界的多候选定位。** 让调用方声明同一授权动作的少量精确候选、有效页面和区域；在同一帧上评估，不为每个候选重新截图。只有唯一命中且通过输入前复核才发送一次。没有匹配、存在竞争操作或出现新窗口时，尽快带回当前证据；不盲选、不重放。
3. **用混合页面检验端到端收益。** 分开测稳定目标、布局迁移、文案切换和真实弹窗。固定起止动作，对比墙钟、切页到点击、截图读取/交付、调用外空档。压测先用合成页面；实机只跑经授权的短路径。性能收益不能以歧义时点击、重复输入或放弃窗口检查为代价。

长会话上下文单独衡量：先比较同一路径的返回大小及恢复一次中断所需调用，再决定是否调整宿主设置。服务端少返回图片和宿主压缩历史是两个不同的机制。
